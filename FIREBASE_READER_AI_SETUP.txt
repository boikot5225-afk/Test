Firebase readerAI migration — что заменить и как запустить

Заменённые/новые файлы:
- index.html
- sw.js
- js/app.js
- js/firebase-config.js
- css/style.css
- reader-ai-test.html
- functions/package.json
- functions/index.js
- firebase.json
- .firebaserc

Что изменено:
1) readerAI в js/app.js больше не вызывает Supabase Edge Function.
   Теперь он вызывает Firebase Callable Function: readerAI.
2) Прямой вызов reader-ai из dictGenerate тоже переведён на общий readerAI().
3) В index.html добавлен firebase-functions-compat.js.
4) Добавлена папка functions/ с Cloud Function readerAI.
5) Сохранён фикс обычного выделения текста в читалке: css/style.css и js/app.js уже включают предыдущий selection-fix.

Первый запуск:
1) В корне проекта:
   npm install -g firebase-tools
   firebase login
   firebase use french-da79a

2) Установить зависимости функций:
   cd functions
   npm install
   npm run lint:check
   cd ..

3) Задать секрет DeepSeek:
   firebase functions:secrets:set DEEPSEEK_API_KEY

4) Деплой функции:
   firebase deploy --only functions:readerAI

5) Открыть reader-ai-test.html через опубликованный сайт, войти в Firebase Auth и проверить кнопки:
   - reader_word
   - translate_paragraph
   - analyze_sentence

Важно:
- Функция в регионе asia-southeast1. Этот регион указан в functions/index.js и js/firebase-config.js.
- Если поменяешь регион функции, поменяй и window.AN2_FIREBASE_FUNCTIONS_REGION в js/firebase-config.js.
- Для Cloud Functions обычно нужен Blaze plan. Firebase может попросить привязать оплату.
- API-ключ DeepSeek не кладём в клиентские JS-файлы. Только Secret Manager.
